# CMG 3D • 4D Platform — 0.4

เครื่องมือดูและแก้โมเดลอาคาร พร้อม BIM Properties และ Timeline 4D ใช้งาน Local ได้ทันที

## เปิดแอป

ต้องใช้ Node.js 22.12+ (ทดสอบด้วย 24.13) ดับเบิลคลิก `Start-CMG.cmd` หรือ:

```powershell
npm ci
npm run dev -- --port 5173 --strictPort
```

เปิด http://localhost:5173 หากพอร์ตมีแอปเดิมอยู่ ให้หยุดตัวเดิมหรือเปลี่ยนพอร์ต ข้อมูล Local แยกตาม origin/พอร์ต

Production: `npm run build` แล้ว `npm start` จะเปิด Node server พร้อมหน้าเว็บและ API ที่ localhost:5173 เปลี่ยนพอร์ตด้วย PORT ได้ การนำเฉพาะ dist ไปวาง static hosting จะใช้ AI ไม่ได้ เพราะต้องมี Node API ด้วย

## แบบ → 3D

1. ลาก PDF, PNG/JPEG/WebP, DWG, DXF, ZIP, RAR และ Timeline CSV ลงในแอป หรือกดอัปโหลด (50 MB ต่อไฟล์)
2. กด **สร้าง 3D ด้วย AI** เลือกไฟล์ที่ต้องการอ่านร่วมกัน ใส่มิติอ้างอิง หน่วย ชั้น และรายละเอียดที่ต้องการ
3. เลือกค่าย/โมเดล/ระดับการคิดในช่อง MCP ได้ทั้ง OpenAI GPT-6 Luna / GPT-6.1 Sol / GPT-6 Astra, Anthropic Claude Opus 5.5 / Sonnet 5.5 และ Google AI Studio Gemini 3.8 Flash / 3.1 Pro Preview โดย GPT-6 Luna และ Extra high เป็นค่าเริ่มต้นสำหรับสร้างโมเดลและแชทแก้ไข
4. กด Admin และเข้าสู่ระบบ Google เพื่อบันทึก MCP API Key ของแต่ละค่ายใน Firebase จากนั้นกด **อ่านและตรวจรายการไฟล์** แล้ว **สร้างโมเดลด้วย AI** ระบบจะส่งงานผ่าน MCP และให้เครื่องมือ MCP ตรวจสอบ/บันทึกผลลงโครงการ
5. อ่านผลลัพธ์และหมายเหตุจาก MCP ได้ในหน้าต่างงาน ไฟล์อ้างอิงยังอยู่ในโครงการเดิม
6. คลิกวัตถุเพื่อดู/แก้ขนาด ตำแหน่ง มุมหมุน วัสดุ โซน แหล่งอ้างอิง และ BIM properties เพิ่มเติม

MCP API Key บันทึกใน Firestore ที่ `CMG-4D-Platform/root/users/{masterEmail}/apiKeys/{openai|anthropic|google}` แยกตามผู้ให้บริการ หน้า Admin สำหรับ MasterAdmin รองรับบันทึก เปลี่ยน และลบ Key โดยแสดงเฉพาะท้าย 4 ตัวอักษร เซิร์ฟเวอร์อ่าน Key ล่าสุดจาก Firebase ก่อนเริ่มงาน MCP

ZIP/RAR แตกในหน่วยความจำ รองรับ archive ซ้อนไม่เกิน 3 ชั้นและ 100 ไฟล์ต่อรอบ RAR ที่เข้ารหัสหรือแบ่ง volume ยังไม่รองรับ ไฟล์ที่อ่านไม่ได้จะแสดงในรายการและไม่ส่งไป AI

DWG ใช้ LibreDWG WASM อ่านพิกัด entities/layers/blocks/units จริง; DXF ใช้ dxf-parser ส่วน PDF และภาพให้เครื่องมือ MCP อ่านจากไฟล์ในโครงการ ไม่ตัดหน้าของ PDF เอง CAD geometry JSON เกิน 1.5 ล้านตัวอักษรต้องแยกชั้น/โซน ปริมาณไฟล์และ context ยังขึ้นกับขีดจำกัดของผู้ให้บริการ

## เครื่องมือ 3D / BIM

- Three.js 0.186.1, React Three Fiber 9.8.1, Drei 10.7.9, Vite 8.3.4 (ตรวจ npm latest วันที่ 9 ตุลาคม 2026)
- หมุน/ซูม/เลื่อนกล้องแบบ damping, render on demand, DPR จำกัดเพื่อลดภาระ GPU, มุม XYZ/ISO และ Perspective/Orthographic
- ชิ้นส่วน 17 ประเภท: ฐานราก ตอม่อ เสา คาน พื้น ผนัง ประตู หน้าต่าง บันได ลิฟต์ หลังคา เหล็กเสริม เสาเข็ม ราว ไม้แบบ นั่งร้าน งานขุด
- ปุ่ม **ย้าย 3D** แสดงแกนลากย้ายพร้อม snap 0.05 m; แก้ขนาดและมุมหมุนในแผงข้อมูลแล้วบันทึก

- ทำสำเนา ลบ และย้อนกลับการแก้โมเดลล่าสุดหนึ่งครั้ง (การลบผนังลบช่องเปิดที่ผูกไว้ด้วย)
- ประตู/หน้าต่างมีกรอบและกระจก ผูก hostId กับผนังแล้วตัดช่องจริง บันทึกช่องเปิดจะจัดเข้าระนาบผนัง และเคลื่อนตามเมื่อย้าย/หมุนผนัง การย่อผนังจนช่องเปิดล้นหรือย้ายช่องเปิดไปทับกันจะถูกปฏิเสธโดยเก็บข้อมูลเดิมไว้
- บันไดกำหนดจำนวนขั้นได้ ลิฟต์มีห้องโดยสาร/ประตู หลังคามีแบบแบนและจั่ว
- เหล็กเสริมสาธิตใช้แท่งทรงกระบอกและ instancing ปรับ cover, diameter, spacing ได้ เหล็กที่ AI อ่านเป็นรายแท่งแสดงเป็นชิ้นส่วน rebar แยกต่างหาก
- ตรวจช่องเปิดผิดแนว/เกินผนัง ประตู/หน้าต่างที่ทับกัน และกล่องชิ้นส่วนประเภทเดียวกันที่หมุนต่างมุมและซ้อนกัน กดรายการเพื่อเลือกชิ้นส่วนได้ การตรวจนี้ใช้ขอบเขตกล่อง ยังไม่ใช่การตรวจผิว geometry ทุกประเภท
- หน่วยภายในเมตร, Z ขึ้น, position เป็นจุดศูนย์กลาง; rotation เป็นองศารอบ Z
- **เปิดบ้านตัวอย่าง** แสดงอาคาร 77 ชิ้นพร้อมองค์ประกอบและ Timeline เพื่อทดลองเครื่องมือ มิติสมมติทั้งหมด ไม่ใช่ผล AI จากแบบผู้ใช้

ชุดสกิลกลางของ Agent อยู่ที่ `src/constructionSkills.mjs` และใช้ร่วมกันทั้งการสร้าง 3D กับการแก้โมเดลด้วย AI: สร้าง 3D, สร้างเหล็กเสริม, งานปูน, งานไม้แบบ นั่งร้าน, งานโครงสร้าง ฐานราก งานขุด และงานสถาปัตย์ เมื่อผู้ใช้สั่ง เช่น “เพิ่มนั่งร้าน” ระบบจะส่งกติกาชุดเดียวกันให้ AI และตรวจผลด้วยหมวด `scaffold` / `formwork`

## 4D และข้อมูล

แนบแผนงาน CSV/PDF พร้อมแบบให้ AI อ่านเพื่อสร้างกิจกรรม หรือกด **แก้แผนงาน** เพื่อกำหนดชื่อ/วันที่และชิ้นส่วนที่เชื่อมเอง หากไม่มีแผนงาน AI จะไม่สร้างวันที่สมมติให้ เล่น/หยุดหรือเลื่อนวันที่เพื่อดูการก่อสร้าง: อนาคตจาง กำลังทำเหลือง เสร็จตามแผนเขียว

หลายโครงการบันทึกใน localStorage ส่วนไฟล์ใน IndexedDB ส่งออก/นำเข้า JSON ได้ (ไฟล์แนบต้องสำรองแยก) มี Firebase Cloud snapshot เดิม ดู [คู่มือ Firebase](docs/FIREBASE_SETUP.md) ไฟล์ IFC ที่แนบสามารถคลิกเพื่อแปลงเป็น Fragments และเปิดในโมเดล 3D ผ่าน That Open Engine ได้

## ความละเอียดและขอบเขต

AI สร้าง geometry แบบพารามิเตอร์จากสิ่งที่อ่านได้ หากไม่มีหมวดตรงตัวสามารถสร้างเป็นชิ้นส่วนกำหนดเองจากกล่อง ทรงกระบอก และท่อเหลี่ยมกลวงได้ ความเหมือนและมิติขึ้นกับต้นฉบับ มิติที่ไม่ทราบควรมี confidence เป็น assumed แสดงในแผงชิ้นส่วน ไม่มีการรับประกันว่าจะตรงทุกจุดจากภาพมุมเดียวหรือแบบที่ไม่มีมิติ รูปทรงอิสระและชิ้นส่วนโค้งยังไม่ครอบคลุมทั้งหมด ตรวจและแก้โมเดลได้โดยไม่ต้องมีขั้นตอนรับรองงานก่อสร้าง

ยังไม่ได้ทดสอบสร้างโมเดลผ่าน API Key จริงของผู้ใช้ การทดสอบ API ใช้ผลจำลองเพื่อยืนยันรูปแบบคำขอ การจัดการ error และข้อมูลที่คืนมา โมเดล/สิทธิ์/เครดิตขึ้นกับบัญชีผู้ใช้

## การตรวจสอบ

แชท AI แสดงขั้นตอนจากเหตุการณ์จริงบน server และรับสถานะสดผ่าน SSE พร้อมสรุปการวิเคราะห์ที่ผู้ให้บริการส่งให้ แยกเวลา heartbeat ของ server ออกจากเวลาความคืบหน้าล่าสุด หากสตรีมขาดจะเชื่อมต่อใหม่และรับประวัติ 100 ขั้นตอนล่าสุดกับสรุปปัจจุบัน หากใช้ SSE ไม่ได้จะตรวจสถานะทุก 3 วินาทีแทน มีปุ่มหยุดงานในแชท

OpenAI รองรับสรุปการวิเคราะห์ระหว่างรับสตรีม ส่วน Anthropic/Google ในเส้นทางปัจจุบันส่งสรุปให้แสดงหลังรับคำตอบครบ การแสดงโมเดล 3D ยังเกิดหลังตรวจผลสำเร็จ สถานะงาน MCP อยู่ใน Firestore และ Cloud Tasks จึงติดตามต่อได้หลัง reload หรือ Cloud Run restart; งานที่ค้างจะถูกส่งซ้ำตามนโยบาย retry ของคิว

ทดสอบสตรีมและ UI โดยใช้ login/AI จำลอง ไม่ใช้ API Key จริง: `node scripts/ai-stream-smoke.mjs` ครอบคลุมข้อความระหว่างรอ เชื่อมต่อใหม่ reload การยกเลิก ช่องทาง polling สำรอง และหน้าจอมือถือ ภาพตรวจอยู่ใน `.qa/ai-stream-*.png`

## สร้างจากแบบและแก้เฉพาะส่วน

ปุ่ม “สร้าง 3D ด้วย AI” ใช้ `/api/mcp/trigger` เพื่อส่งคำขอผ่าน MCP โดย API ตอบรับงานก่อน แล้ว Cloud Tasks ให้ Cloud Run ทำงานต่อและหน้าเว็บติดตามสถานะจาก Firestore งาน AI จึงไม่ค้างรอภายใน Firebase Hosting ซึ่งตัด request ที่เกิน 60 วินาที สำหรับ OpenAI worker จะดาวน์โหลดไฟล์ที่เลือกจาก Firebase Storage แล้วแนบ PDF/ภาพเข้า Responses โดยตรงเพื่อให้โมเดลเห็นหน้าแบบและมิติจริง ส่วน MCP ใช้ตรวจ file ID และบันทึกผลลงโครงการ หากต้องการแก้โมเดลที่บันทึกแล้ว ให้ใช้ “Chat AI · แก้ไขโมเดล 3D” ใต้โมเดล

แชทแก้ใช้ `/api/mcp/trigger` โดยให้ MCP ค้นหา ID/ชื่อ/ประเภท/ข้อมูลชั้นจากโมเดลล่าสุด หรือใช้ “ชิ้นที่เลือก” หลังคลิกชิ้นใน 3D รองรับชื่อกลุ่ม เช่น “บันได ST6 ทั้งหมด” จากส่วนของ ID ชื่อ หรือ BIM properties โดยแยก ST6 ออกจาก ST60 หากไม่สั่งทั้งกลุ่มและพบหลายชิ้นให้ระบุ ID หรือเลือกก่อน คำสั่งหนึ่งรองรับเป้าหมายไม่เกิน 100 ชิ้น และส่งประวัติสนทนาล่าสุดไม่เกิน 10 บอลลูนให้ผู้ให้บริการที่เลือก

AI คืนเฉพาะ `{updates,adds,removes,notes}` ชิ้นส่วนบริบทที่ไม่ใช่เป้าหมายอ่านได้อย่างเดียว ระบบตรวจรายการแก้ไขแล้วผนวกกับโมเดลล่าสุด โดยรักษาชิ้นส่วนอื่น เอกสาร ประวัติแชท และแผนงาน ตรวจว่าข้อมูลเป้าหมายและบริบทไม่เปลี่ยนระหว่างรอ AI และตรวจช่องเปิด/การซ้อนทับใหม่กับโมเดลทั้งหมดด้วยโค้ด การย้ายผนังจะย้ายช่องเปิดที่เชื่อมกัน การลบผนังจะลบช่องเปิดที่เชื่อมและเก็บลิงก์แผนงานให้ถูกต้อง แก้โมเดลผ่านหน้าหลักแล้วย้อนกลับได้ หากต้องการข้อมูลจากแบบเพิ่ม AI จะอธิบายใน notes แทนการอ่านแบบทั้งหมดอัตโนมัติ

ทดสอบกระบวนการแยกสร้าง/แก้และการส่งเฉพาะส่วนด้วย `node scripts/model-edit-smoke.mjs` ใช้ login/AI จำลอง ครอบคลุมส่ง 2 จาก 503 ชิ้น รักษางานแก้ด้วยมือ เลือกชิ้น ความคลุมเครือ reload ผลลัพธ์เก่า และหน้าจอมือถือ ภาพตรวจอยู่ใน `.qa/model-edit-*.png`

```powershell
npm test
npm run build
npm run mcp:smoke
# เปิด dev server ที่ 5174 ก่อน หรือกำหนด QA_URL
node scripts/smoke.mjs
node scripts/modeling-smoke.mjs
node scripts/verify-native.mjs
```

UI tests ใช้ Microsoft Edge ที่ติดตั้งในเครื่อง (headless) ภาพอยู่ใน .qa/ ซึ่งไม่เข้า Git `verify-native.mjs` ดาวน์โหลดตัวอย่าง DWG/RAR จาก repository เจ้าของไลบรารีแล้วตรวจการอ่านจริง

เอกสาร API ที่ใช้: [OpenAI vision](https://developers.openai.com/api/docs/guides/images-vision), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Claude models](https://platform.claude.com/docs/en/models/overview), [Claude vision](https://platform.claude.com/docs/en/build-with-claude/vision)

## Admin และการทดสอบ Firebase

Firestore rules สำหรับ API Keys เผยแพร่ในโปรเจกต์ cmg-4d-platform แล้ว โดยรักษา Rules ของข้อมูล CMG เดิมไว้ Admin เป็นการจัดการ Key ของบัญชีตนเอง ไม่ใช่หน้าดู Key ของบัญชีอื่น

ทดสอบแบบไม่ใช้ Key จริง:

```powershell
firebase emulators:start --only auth,firestore --project demo-cmg-admin --config firebase.test.json
node tests/firebase-keys.mjs
# เปิดอีก terminal เพื่อทดสอบ UI กับ Emulator
$env:VITE_FIREBASE_EMULATORS="1"
$env:VITE_FIREBASE_PROJECT_ID="demo-cmg-admin"
npm run dev -- --port 5175 --strictPort
# เปิด terminal อีกอัน
node scripts/admin-smoke.mjs
```

ห้ามใช้ VITE_FIREBASE_EMULATORS=1 กับแอปจริง ค่า test นี้ไม่ได้บันทึกลง .env การสร้างโมเดลจริงยังต้องใช้เครดิตและสิทธิ์ของ Key แต่ละค่าย


## Authentication และ Realtime Projects

ระบบเพิ่ม Google / Email-Password login แบบ persistent session, MasterAdmin คนแรก, approval, หลาย Role, โปรไฟล์ Google, จัดการผู้ใช้ใน workspace, แชร์/Assign Project และ realtime autosave ที่คง draft เมื่อมีการแก้ไขชนกัน ดู [การตั้งค่าและตัวอย่าง AuthContext / LoginPage](docs/AUTHENTICATION.md) ก่อนเปิดใช้งาน Firebase จริง API Key ที่ MasterAdmin จัดการถูกใช้บน server ผ่าน Firebase Admin SDK

## MCP · ช่องทางเดียวสำหรับ AI

ทั้งการสร้างโมเดลจากแบบและการแก้โมเดลใช้ MCP เท่านั้น ไม่มีตัวเลือกวิธีทำงานแบบ API เดิมในหน้าต่าง AI ผู้ใช้เลือกค่าย โมเดล และระดับการคิดได้ในช่องคำสั่งแต่ละจุด ส่วนหน้า Admin ใช้สำหรับบันทึก MCP API Key ของทั้งสามค่าย

เส้นทาง MCP คือ Webapp → Cloud Run `/api/mcp/trigger` → Cloud Tasks → Cloud Run worker → ผู้ให้บริการที่เลือก → Custom MCP `/mcp` → Firebase Admin/Firestore โดย OpenAI ใช้ Responses MCP ส่วน Anthropic และ Google ใช้ MCP bridge ฝั่งเซิร์ฟเวอร์ที่เรียกเครื่องมือชุดเดียวกัน หน้าเว็บติดตามสถานะจาก Firestore และมีปุ่มยกเลิกงาน MCP เอกสารตั้งค่า Google Cloud อยู่ที่ [GOOGLE_CLOUD_MCP_DEPLOYMENT.md](docs/GOOGLE_CLOUD_MCP_DEPLOYMENT.md) และแผนงานทั้งหมดอยู่ที่ [MCP_IMPLEMENTATION_PLAN.md](docs/MCP_IMPLEMENTATION_PLAN.md)

อย่าใส่ `MCP_SERVER_TOKEN` หรือ `MCP_SCOPE_SECRET` ใน frontend หรือชื่อตัวแปรที่ขึ้นต้นด้วย `VITE_` ให้เก็บใน Secret Manager/Cloud Run เท่านั้น
